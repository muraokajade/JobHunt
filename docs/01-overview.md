# JobHunt Overview

## 1. JobHuntとは

JobHuntは、転職と副業の求人・案件を1か所に登録し、応募後の選考状況まで管理する個人向けWebアプリです。
求人ページのURLを貼ると、サーバー側でページを取得して案件名・報酬・締切などを読み取り、登録フォームの下書きを作ります。
登録後は、ステータスの更新、活動メモ、ゴミ箱での整理までを同じ画面で行います。
ユーザーごとにデータを分けて保存し、PCでもスマートフォンでも使えます。

## 2. 開発した背景

自分自身の転職活動で、次の問題がありました。

- 求人情報が複数の媒体に分散し、どこで見た求人だったかを後から探し直すことになる
- 応募したあと、どの企業がどの選考段階にいるのかを追いにくい
- 面接日程の連絡など、企業から後で届いた情報を残しておく場所がない

これを解決するために、自分が実際に使うツールとして開発しました。
最初は副業(クラウドソーシング)案件の管理として作り始め、転職活動に合わせて転職求人も扱えるように拡張しました。
現在も自分の転職活動で使いながら改善しています。

## 3. 解決する課題

| 問題 | JobHuntでの扱い |
|---|---|
| 求人が複数媒体に散らばる | 求人URLから取り込むか手入力で、1つの一覧に集める。URLから媒体(type・CrowdWorks・MENTA・Lancers・フリーランスハブ)を判定する |
| 求人情報を手で書き写すのが面倒 | 求人ページの構造化データ(JSON-LD)やOGPなどから、案件名・会社名・報酬・締切・勤務地・副業可否などを読み取り、登録前に確認・修正できる下書きにする |
| 同じ求人を二重に登録してしまう | URL取込の時点で、同じURLの登録済み案件があれば警告する(登録自体は止めない) |
| 応募後の状況が追えない | 転職・副業それぞれの選考段階をステータスで管理し、一覧を「選考が進んでいる順」に並べる |
| 後から届いた情報が残らない | 案件ごとの「活動メモ」に、日程連絡や確認事項を書き足していく |
| 不要になった案件の整理 | ゴミ箱へ移動し、必要なら復元、不要なら完全削除する |

## 4. 主な機能

**登録**

- 求人URL取込: URLを貼ると、サーバー側でページを取得・解析し、登録フォームの下書きを作る(保存は利用者が確認してから)
  - 取得には SSRF 対策を入れている(非公開IPへの接続拒否、DNSで解決したIPへの接続固定、リダイレクトごとの再検証など)
  - ログインが必要なページ(応募履歴ページなど)や取得に失敗したページは、URLを引き継いで手入力へ案内する
- 手入力: 同じ登録フォームで、全項目を手で入力する
- 新規登録時のステータスは「応募済み」から始まる(変更可能)

**管理**

- 転職 / 副業の分類: 種別ごとにステータスの体系と専用項目(転職: 職種・勤務地・雇用形態・副業可否など / 副業: 契約形態・納品日など)が異なる
- ステータス管理: 転職は 気になる〜内定・見送り の8段階、副業は 気になる〜完了・見送り の12段階。詳細画面から直接変更でき、変更は履歴としてDBに記録される
- 一覧: 選考の進み具合 → 更新日時 の順に並ぶ。対応中・終了・お気に入りの件数を表示する
- 絞り込み・検索: 「すべて / 転職 / 副業」の切り替えと、案件名・会社名・募集内容・メモのキーワード検索
- 詳細表示: PCでは右側のパネル、スマートフォンでは下からのシートで表示する
- 編集: 登録と同じフォームで、全項目を後から修正する
- 活動メモ: 案件ごとの自由記述欄。詳細画面から追加・編集できる
- 次アクション: 次にすることと、その予定日を記録する項目
- お気に入り: 案件に印を付け、一覧と詳細に表示する
- ゴミ箱: 削除した案件の一覧・復元・完全削除

**その他**

- 認証: ユーザー登録・ログイン・ログアウト。案件はユーザーごとに分離され、他人の案件は参照・変更できない
- 初回案内: まだ案件が無いときは、登録方法の案内を表示する
- デモ: 架空の案件4件で画面を体験できる閲覧専用モード。サーバーへの保存や通信は行わない

## 5. 基本利用フロー

```
求人を見つける
  ↓
求人URLを貼って取り込む(取り込めないページは手入力)
  ↓
取り込まれた内容を確認・修正する(同じURLの登録済み案件があれば警告)
  ↓
登録する(ステータスは「応募済み」から開始)
  ↓
選考が進んだら、詳細画面からステータスを更新する
  ↓
企業から届いた連絡や面接日程を、活動メモに書き足す
  ↓
内定・見送り(副業は完了・見送り)まで管理し、不要になればゴミ箱へ
```

## 6. 技術スタック概要

詳細は後続のドキュメントで説明します。

| 区分 | 技術 |
|---|---|
| Frontend | React 19 / TypeScript / Vite / Tailwind CSS 4(UIライブラリは使わず自作) |
| Backend | Laravel 13(PHP 8.4)。フロントエンドと同じオリジンからJSON APIを提供する |
| Database | 本番: PostgreSQL(Neon) / ローカル・テスト: SQLite |
| Authentication | Laravelのセッション認証(Cookie + CSRFトークン)。公開LP(`/`)はログイン不要で、アプリ本体(`/app`)とAPIはログインで保護する。加えて、入口をBasic認証で保護する仕組み(パスワードを設定すると有効。本番では未使用) |
| Test | Frontend: Vitest + Testing Library(289件) / Backend: PHPUnit(420件) |
| Deployment | Dockerのマルチステージビルド(Node 24でフロントエンドをビルド → PHP 8.4 / FrankenPHP)を Vercel 上で実行 |
| CI | GitHub Actions(main への push / pull request で、Frontend のテスト・型チェック・ビルドと Backend のテストを実行) |

テスト件数は 2026年10月時点のものです。

## 7. 実運用からの改善

自分で使う中で見つかった問題と、その対応です(Git履歴で確認できるもの)。

| 使っていて困ったこと | 対応 |
|---|---|
| 一覧に情報が多すぎて、どの案件がどうなっているのか一目で分からない | 一覧に出す項目を比較に必要な値(案件名・種別・ステータス・報酬・締切・会社)に絞った(2026-09-01)。さらに1行ずつの表形式にして、詳細はPCの右パネル / スマートフォンの下シートへ分けた(09-26) |
| ステータスを1つ変えるだけでも、編集フォームを開いて保存する必要があった | 詳細画面からステータスだけを直接変更できるようにした(09-26) |
| 一覧で選考の段階を見分けにくい | ステータスを「未着手 / 選考中 / 成功 / 見送り」の4グループで色分けした。段階を示すメーターも試したが、列幅を圧迫してステータス名や種別が読めなくなったため、小さな点と文字の表示に戻した(09-26〜27) |
| 登録するのはほとんど応募した求人なのに、初期ステータスが「気になる」だった | 新規登録の初期ステータスを「応募済み」に変更した(09-30) |
| 一覧が登録順で、選考が進んでいる案件が埋もれる | 選考の進み具合が大きい順、同じなら更新日時の新しい順に並べるようにした。見送り・副業の完了は進行中の案件より下に置く(09-30) |
| 企業から後で届いた情報を残す場所がない | 案件ごとの「活動メモ」を、詳細画面から追加・編集できるようにした(09-30) |
| ログインが必要な応募履歴ページのURLを貼ると、取込が失敗して登録が止まる | 事前に判定し、URLを引き継いだまま手入力へ案内するようにした(09-02) |
| 取込が応答しないページで、画面が待ち続ける | 接続・全体の時間上限を設け、待ち続けないようにした(09-05) |
| 同じ求人を二重に登録してしまう | 取込時に同じURLの登録済み案件を警告するようにした(09-21) |
| 求人ごとの副業可否を記録できなかった | 転職求人の項目に副業可否(可 / 不可 / 不明)を追加し、求人ページの記載から読み取るようにした(09-22) |

このほか、まだ案件が無い利用者向けに、登録方法の案内と架空案件で試せるデモを追加しました(09-26)。
また、ポートフォリオとして公開する前に、URL取込のSSRF対策を見直して強化し(10-01)、GitHub ActionsでCIを導入しました(10-01)。

## 8. 現在の位置づけ

- 個人開発: 設計・実装・テスト・デプロイ・運用を1人で行っている(2026年8月に開発開始)
- 実利用中: 自分の転職活動で使っている
- 本番環境: DockerイメージをVercel上で実行し、データベースにはNeon(PostgreSQL)を使って運用している
- 継続改善: 実際の利用で見つかった問題を、上記のように継続的に直している
- ポートフォリオ: ソースコード、テスト、CIの実行結果をGitHubで公開している
